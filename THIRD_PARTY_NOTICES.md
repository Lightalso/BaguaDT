# Third-party components

BaguaDT source is MIT licensed. Third-party components retain their own licenses.

- **Qt 6.8.3**: https://www.qt.io/licensing/ and https://doc.qt.io/qt-6/licensing.html . Dynamically linked; the application can be rebuilt against compatible replacement Qt libraries. Matching source: https://download.qt.io/archive/qt/6.8/6.8.3/single/qt-everywhere-src-6.8.3.tar.xz .
- **Project Chrono 10.0.0**: BSD-3-Clause; https://github.com/projectchrono/chrono . License included in `licenses/Chrono-LICENSE` in the binary package. Bundled third-party source notices are retained in the local Chrono source tree.
- **libuipc** (fixed local build in `.deps/hsc-native`, from https://github.com/spiriMirror/libuipc ): Apache-2.0. It provides the native backend's ABD/FEM/IPC/CCD simulation and CUDA infrastructure; `scripts/BuildHscNative.ps1` fetches, patches and builds it into `BaguaHscNative.dll`, which is redistributed together with the `uipc_*.dll` modules it produces. License and notice are included as `licenses/libuipc-LICENSE` and `licenses/libuipc-NOTICE`; the embedded METIS/GKlib notices are retained in that notice. The libuipc build links further open-source libraries (for example oneTBB, spdlog, fmt, Eigen) that keep their own licenses.
- **Eigen 3.4.0**: primarily MPL-2.0; https://eigen.tuxfamily.org/ . Used by Chrono, libuipc and the application HSC reference solver; notices included in `licenses` in the binary package.
- **NVIDIA CUDA Toolkit 13.4**: https://docs.nvidia.com/cuda/eula/ . CUDA runtime is statically linked; GPU operations require a compatible NVIDIA driver.
- **Microsoft Visual C++ runtime**: Microsoft redistributable components, deployed by Qt's Windows deployment tool.

The binary package contains no Qt SDK, Chrono source tree or CUDA development toolkit.

The HSC example in `examples/HSC` contains converted results from the user's HSC reproduction project and Chrono-derived vehicle geometry. The example runs as a data replay; it does not need a solver at all. The source notices and full Chrono asset license are retained alongside the data. Native-run provenance, parameters, trajectories and HSC statistics are retained under `examples/HSC/provenance`. These are replacement vehicle assets, not the HSC paper's original scene or a claim of paper performance reproduction.

The application-owned CPU HSC reference implementation in `src/Hsc.cpp` implements the published mathematical method and an adapted residual-correction extension. The CUDA linear solver in `src/HscCuda.cu` and its native counterpart `native/LinearHsc.cu` are adaptations of the local reproduction project's `linear_hsc.cu`, plugged into libuipc's linear-solver interface (Apache-2.0, see above). No upstream libuipc Python bindings or author-provided prebuilt HSC binaries are redistributed. Research sources and deviations are documented in `docs/HSC_INTEGRATION.md`. The manufactured linear-system fixture in `tests/data/hsc-reference.json` was generated by the supplied reproduction project, with its source hash retained in the fixture.
